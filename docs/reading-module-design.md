# 双语职事书报阅读模块设计方案

## 目标

用户上传同一本书的英文版和中文版，系统自动提取章节与段落、生成中英文段落匹配结果，经用户校对后，生成英文在左、中文在右的对照阅读页面，帮助提高英文阅读理解能力，并与生词本联动。**不涉及跟读/朗读评分**——这个模块只服务阅读，发音练习仍然走现有的跟读页面。

## 用户流程

```text
上传英文版 + 中文版
        ↓
文本提取 / 结构化解析
        ↓
章节与段落识别
        ↓
自动段落对齐
        ↓
人工校对（全部待确认，不分置信度等级）
        ↓
发布双栏阅读材料
```

## 支持格式与解析

按实际手头资料定：

- **英文**：PDF，且仅支持文本层可直接选中复制的那种——直接用文本层提取，不需要 OCR。扫描版/图片版 PDF 不在这期范围内，放到后续阶段。
- **中文**：优先支持 EPUB（本质是结构化的 XHTML，章节按文件拆分、段落是 `<p>` 标签，解析成本最低、结构最干净），同时支持 DOCX（用 `python-docx` 读段落，靠"标题 1/标题 2"这类样式识别章节层级）。

解析要处理：

- 自动识别书名、章节、标题。
- 忽略重复出现的页眉、页脚、页码（PDF 端常见），保留正文段落顺序。
- PDF 端额外处理软换行导致的段落被拆断的问题（同一段落跨行时先拼接回一整段，再按空行/缩进识别真正的段落边界）。
- 英文版和中文版分别保存原始文件，解析结果可重新生成（改了解析逻辑不用重新上传）。

## 段落对齐（章节位置 + 字数比例 + 语义相似度）

对齐以段落为基本单位，不强制逐行对齐：

- 一对一：一个英文段落对应一个中文段落。
- 一对多 / 多对一。
- 手动匹配：自动判断不了时由用户选。

自动匹配综合三个信号算加权得分：

- **章节内段落位置**：同一本书英文版和中文版章节顺序一致，段落大致按顺序推进。
- **字数比例**：中英文字数比例在同一本书内通常稳定，偏离典型比例太多的候选直接降权。
- **语义相似度**：用本地跑的多语言句向量模型（比如 `paraphrase-multilingual-mpnet-base-v2` 或 LaBSE）把中英文段落各自编码成向量，算余弦相似度。跟 Whisper 一样在本机跑、不调外部 API，你的书不会离开本地；首次使用需要联网下载一次模型，之后离线可用（README 里 Whisper 那条说明可以照抄这个模式）。

三个信号加权合并成一个匹配得分，同时作为**置信度**保留下来——不是为了自动发布，所有结果依然要走人工确认，但校对页面可以按置信度排序/高亮，让你优先看最可能出错的那些，比全部平等对待更省时间。段落合并/拆分、经节引用、脚注这类语义模型也判断不准的情况，照样会指望人工校对兜底。

示例数据：

```json
{
  "chapter": "Chapter 1",
  "paragraph_id": "ch1-p003",
  "english": "The divine life is being dispensed into us.",
  "chinese": "神圣的生命正分赐到我们里面。",
  "alignment_type": "one_to_one",
  "confidence": 0.91,
  "status": "pending_review"
}
```

## 校对页面

校对页面显示英文段落、中文段落、匹配状态和置信度。低置信度结果排在前面/高亮显示，方便优先处理最可能出错的段落。用户可以：

- 合并或拆分段落。
- 上移或下移段落。
- 重新选择对应段落。
- 标记标题、经节、注释或忽略内容。
- 手动编辑译文。
- 确认单个段落或整章结果。

只有校对通过的内容才能发布到阅读中心。

## 双栏阅读页面

- 左侧英文，右侧中文；桌面端双栏，移动端上下排列。
- 以 `paragraph_id`（对齐组）关联中英文，**点击一侧高亮另一侧对应段落**，同时两侧同步滚动。
- **同步滚动机制**：两栏按对齐组分别打锚点（`data-group-id`）。用 `IntersectionObserver` 监测"主动滚动的那一侧"当前哪个组最靠近顶部，算出它在视口内的相对位置，再把另一侧对应组程序化滚动到同样的相对位置；程序化滚动期间临时挂一个标志位，避免触发对方的滚动监听、形成两侧来回抢滚动的反馈循环。
- **已知局限（不是要解决的 bug，是对齐粒度带来的效果）**：对齐是段落级的，不是句子级。遇到很长的段落，或者一对多/多对一分组时，中途两栏会有点跟不齐，读到下一个对齐组边界才会重新对上——这是"段落级对齐"这个设计本身的取舍，除非上句子级对齐，否则做不到逐句精确同步。
- 阅读进度（章节 + 段落）自动保存到后端数据库，不用 `sessionStorage`——这是要长期留存的学习记录，跟现在跟读页"关掉标签页就可能丢"的临时状态不是一回事。
- 支持显示/隐藏中文、调整字体大小、行距和阅读主题。
- **双击**单词查看释义、翻译并加入生词本——跟跟读页保持同一套手势，不用单击或右键，免得自己记混。
- 职事专有词汇使用统一术语库翻译和解释。

明确不做：段落跟读、朗读评分。这个模块的目标是提高阅读理解能力，不接入 Azure 发音评分；发音练习仍然用现有跟读页面。

## 生词本联动

- 从阅读页标记的生词**不生成音频**——没有原声可截取，也不合成美式/英式发音，跟音频来源的生词卡片不是一回事。
- 卡片只需要：单词、释义/翻译、词性、来源句子（英文原句，等价于现在的 `context_text`）。
- 数据模型改动：`VocabWord.media_id`、`sentence_id` 目前是非空外键，需要改成可空，并新增来源字段区分"来自音频"还是"来自书"（例如 `source_type: 'media' | 'book'` + `book_paragraph_id`）。这是安全的 `ALTER TABLE`，不影响已有数据。
- `word_norm` 目前是全局唯一约束：同一个词如果先在音频里标过，之后在书里再标，会直接命中旧记录，例句还是音频里那句，不会换成书里的例句。这次先维持这个行为不变——个人学习场景下影响不大，以后如果实际用起来觉得别扭，再改成允许同一个词有多条来源不同的记录。

## 与现有模块的联动

- 阅读中心：管理书籍、章节、阅读进度、发布状态。
- 生词本：从英文正文直接收藏单词（只存例句，不生成音频）。
- 术语库：统一双语职事术语的翻译和解释。
- 学习统计：记录阅读时长、完成章节数、新增生词数。

## MVP 开发范围

第一阶段实现：

1. 双文件上传（英文 PDF + 中文 EPUB/DOCX）。
2. PDF 文本层提取、EPUB/DOCX 结构化解析——三种格式都要做，因为这就是手头实际有的资料，不是可以先跳过的。
3. 章节与段落识别，含 PDF 页眉/页脚/页码清洗和软换行拼接。
4. 段落级自动对齐：章节位置 + 字数比例 + 本地多语言句向量语义相似度，加权得出置信度。
5. 校对页面，按置信度排序/高亮，全部人工确认后才能发布。
6. 英文左、中文右的双栏阅读页面：点击互相高亮 + 按对齐组同步滚动。
7. 阅读进度落库、生词本联动（无音频）。

后续阶段：扫描版 PDF 的 OCR 支持、批量导入、更复杂的脚注/经节引用处理、句子级对齐（如果段落级同步滚动的错位感实际用起来还是明显，再考虑升级粒度）。

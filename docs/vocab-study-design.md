# 生词本学习与复习模式设计方案

> 状态：待评审  
> 范围：仅产品、交互与技术设计，不包含本阶段代码实现  
> 参考：用户提供的「不背单词」界面截图，仅借鉴沉浸式学习流程和极简信息层级，不复制品牌视觉或素材

## 1. 背景

当前「生词本」已经支持查看单词、筛选状态、播放原声/美式/英式发音、删除以及导出词表，但仍然是一个静态收藏列表。用户需要主动决定学什么、何时复习，也无法通过学习反馈形成长期记忆计划。

本功能将生词本扩展成完整的学习闭环：

1. 生词进入待学习队列。
2. 用户按组学习，并用「认识 / 模糊 / 不认识」评价回忆结果。
3. 系统依据艾宾浩斯遗忘规律的间隔原则安排复习。
4. 每次复习结果动态缩短或延长下一次间隔。
5. 单词逐渐进入已掌握状态，但仍保留低频维护复习。

## 2. 设计目标

- 用户打开生词本后，能立刻知道今天要学习和复习多少词。
- 用户可以分别设置每组新词数与每组复习词数。
- 学习页保持专注，单屏只处理一个单词。
- 先触发主动回忆，再展示答案，降低「看见释义就以为记住」的错觉。
- 复习时间由记忆阶段和实际反馈共同决定，而不是只靠手动状态。
- 所有学习状态保存在本地 SQLite 数据库，重启应用后可继续。
- 缺少 DeepSeek 或 Azure 配置时，学习流程仍可使用已有内容正常运行。

## 3. 非目标

第一版暂不包含：

- 排行榜、金币、连续签到奖励等强游戏化机制。
- 拼写、听音选义、选择题等多题型。
- 云端同步、跨设备同步与账号系统。
- AI 自动生成助记图、词根树或更多例句。
- 完整复刻「不背单词」的摄影背景、品牌色和动效。

## 4. 核心概念

### 4.1 状态

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| 新词 | 已加入生词本，但还没有完成首次学习 | 新增生词时 |
| 学习中 | 已学习，正在按计划复习 | 完成首次评价后 |
| 已掌握 | 已通过多个递增间隔的复习 | 达到掌握条件后自动进入 |
| 暂缓 | 暂时不进入每日任务，但保留在词库 | 用户手动设置 |

`新词 / 学习中 / 已掌握` 应由学习记录自动维护，不再建议用户在列表中循环点击切换。列表可提供「重置学习进度」和「暂缓学习」等明确操作。

### 4.2 每组数量与每日上限

- 每组学习单词数：控制一轮新词任务的长度，默认 `5`。
- 每组复习单词数：控制一轮复习任务的长度，默认 `10`。
- 每日新词上限：控制当天最多引入多少新词，默认 `20`。
- 到期复习不设置硬性每日上限，只按组拆分，避免过期任务被永久推迟。

例如今天有 23 个到期词，每组复习 10 个，则分为 `10 + 10 + 3` 三组；完成一组后由用户决定继续还是休息。

## 5. 信息架构

### 5.1 路由建议

| 路由 | 页面 |
| --- | --- |
| `/vocab` | 生词本首页与单词管理 |
| `/vocab/session?mode=review` | 到期复习会话 |
| `/vocab/session?mode=learn` | 新词学习会话 |
| `/vocab/session?mode=mixed` | 今日任务，先复习后学习 |
| `/vocab/settings` | 学习设置；也可实现为首页抽屉 |

学习会话页进入专注模式，隐藏全局顶部导航；退出后返回生词本首页。

### 5.2 生词本首页

首页分为「今日任务」和「全部单词」两层：

```text
生词本                                                设置
把遇见的词，变成真正会用的词。

今日任务
26 个待复习 · 12 个新词
[ 开始今日任务 ]

┌──────────────────┐  ┌──────────────────┐
│ 学习新词          │  │ 到期复习          │
│ 12 个 · 每组 5    │  │ 26 个 · 每组 10   │
└──────────────────┘  └──────────────────┘

学习中 48             已掌握 126            今日完成 20

──────────────────────────────────────────────
全部单词    新词    学习中    已掌握    暂缓       搜索
现有单词卡片列表……
```

规则：

- 主按钮「开始今日任务」默认先处理到期复习，再进入新词学习。
- 用户直接选择「学习新词」但仍有到期任务时，显示轻量确认框，不强制阻止。
- 没有到期任务时显示「今日复习已完成」。
- 没有新词时，学习卡显示「暂无新词」，同时保留复习入口。
- 所有任务完成后，主按钮变为「今日任务已完成」，仍可进入自由复习。

## 6. 学习会话

### 6.1 单词卡的两个阶段

每个单词都经历「主动回忆」和「答案确认」两个画面。

#### 阶段 A：主动回忆

```text
‹ 退出                     3 / 10                   ···


                         exhilarating   🔊
                         /ɪɡˈzɪləreɪtɪŋ/

               I’d never done that before. It was ________.


           想起词义后再选择；不确定时请选择「模糊」

                认识          模糊          不认识
                 1             2              3
```

- 默认自动播放用户选定的美式或英式发音；没有标准发音时使用原声音频。
- 原句中的目标词默认挖空，帮助用户利用语境回忆。
- 新词与复习词均先回忆，避免被动浏览。
- 点击评价后立刻记录选择，并进入答案阶段。
- 若该词存在跟读弱项记录，显示「发音待加强」提示；它只提供学习线索，不替用户判断词义是否记住。

#### 阶段 B：答案确认

```text
                         exhilarating   🔊
                  adj. 使人兴奋的，令人振奋的

┌────────────────────────────────────────────┐
│ I’d never done that before. It was exhilarating. 🔊 │
│ 我以前从没这么做过，真的令人兴奋。               │
└────────────────────────────────────────────┘

英文释义 / 词形变化 / 更多内容                         展开

                         [ 下一词 ]
```

- 第一层只突出词性、主释义与来源原句。
- 英文释义、词形变化和其他扩展内容折叠，避免信息过载。
- 显示刚才的评价，并允许在进入下一词前改选一次。
- 「不认识」的词会在本组后部再次出现，答案页需明确提示「本组稍后再见」。

### 6.2 三档反馈

| 反馈 | 用户含义 | 会话内行为 | 排期行为 |
| --- | --- | --- | --- |
| 认识 | 无提示即可迅速说出核心词义 | 不重复 | 推进一个记忆阶段 |
| 模糊 | 大致知道，但需要思考或只记得部分 | 本组后部再出现 1 次 | 不推进阶段，缩短下一间隔 |
| 不认识 | 无法回忆或答案明显错误 | 本组后部再出现，最多 2 次 | 回到短期巩固阶段 |

同一单词在一个会话中的补强重复不计入新的正式复习轮次，以免人为夸大学习次数。

### 6.3 组内重复

- 「模糊」在至少间隔 3 张其他卡片后重现一次。
- 「不认识」在至少间隔 3 张卡片后重现；若仍不认识，可在组末再出现一次。
- 单词每组最多额外出现 2 次，避免难词造成无限循环。
- 组内最后几个词不足以形成间隔时，放到组末的「再巩固」小节。

### 6.4 中途退出

- 每次评价后立即写入数据库，不等待整组完成。
- 未评价的单词不改变学习状态。
- 下次进入时提示「继续上次进度」或「重新开始本组」。
- 重新开始只重建未完成队列，不撤销已经提交的评价。

### 6.5 完成页

```text
本组完成

认识 14        模糊 4        不认识 2
用时 6 分 18 秒

下一次复习：明天预计 8 个词

[ 继续下一组 ]       [ 返回生词本 ]
```

结果页强调完成情况和下一次安排，不使用金币或竞争排名。

## 7. 复习排期设计

### 7.1 原则

艾宾浩斯曲线描述遗忘会随时间快速发生并逐渐放缓，但不能直接给出适用于每个人、每个单词的唯一日期。因此第一版采用「基础间隔 + 反馈修正」：

```text
10 分钟 → 1 天 → 3 天 → 7 天 → 15 天 → 30 天 → 60 天 → 120 天
```

其中 10 分钟阶段主要由组内补强承担；如果用户已经退出应用，则保留精确的 `due_at`，下次打开时作为到期复习出现。

### 7.2 阶段推进

定义记忆阶段 `stage = 0...7`，对应上述基础间隔。

#### 选择「认识」

- `stage = min(stage + 1, 7)`。
- `due_at = 当前时间 + 新阶段对应间隔`。
- 连续「认识」次数加一。

#### 选择「模糊」

- 阶段不推进。
- `stage = 0` 时，下次为 10 分钟后。
- `stage > 0` 时，下一间隔取当前阶段基础间隔的 50%，但最短为 1 天。
- 连续「认识」次数清零。

#### 选择「不认识」

- `stage = 0`。
- 下次正式复习为 10 分钟后。
- 遗忘次数 `lapse_count + 1`。
- 连续「认识」次数清零。

### 7.3 掌握条件

满足以下条件时自动标记为已掌握：

- 已达到 `stage >= 6`，即成功进入至少 60 天间隔；并且
- 最近连续 3 次评价均为「认识」。

已掌握并不意味着永久移出计划：

- 继续按 120 天进行低频维护复习。
- 若选择「模糊」，回到学习中并缩短间隔。
- 若选择「不认识」，重置为阶段 0 并回到学习中。

### 7.4 到期队列排序

到期复习按照以下优先级排序：

1. `due_at` 最早，即逾期最久的单词优先。
2. 同样到期时，遗忘次数更多的优先。
3. 再相同时，有跟读弱项记录的单词优先。
4. 最后按最近学习时间更早的优先。

`WeakWordCount` 只作为同等到期条件下的次级排序信号，不能自动把用户的记忆评价设为「模糊」或「不认识」。它是只增不减的历史计数，不足以单独代表当前记忆强度。

新词队列默认按加入生词本的时间从早到晚，避免早期收藏长期沉底。后续可增加随机顺序，但第一版不需要。

### 7.5 跨天与时区

- 数据库存储 UTC 时间，界面按系统本地时区显示。
- 「今天」以用户系统当地时间的自然日为准。
- 用户修改系统时区后，以新的本地时间重新判断是否到期，但不改写历史记录。
- 应用长期未打开时，所有逾期词都保留，不因跨天丢弃。

## 8. 学习设置

```text
学习设置

每组学习新词             −   5  +
每组复习单词             −  10  +
每日新词上限             −  20  +

任务顺序
● 先复习后学习
○ 学习与复习混合

自动播放发音             开 / 关
首选发音                 美式 / 英式 / 原声
回忆时显示来源原句       开 / 关

恢复默认                                  保存
```

约束建议：

- 每组新词：`5–50`。
- 每组复习：`5–100`。
- 每日新词上限：`0–200`；`0` 表示当天暂停引入新词。
- 设置只影响之后创建的组，不修改已经进行中的会话。

设置存储在本地数据库，而非仅存浏览器 `localStorage`，保证桌面应用升级或前端缓存清理后仍然存在。

## 9. 视觉设计

### 9.1 总体方向

- 参考截图的单任务、低干扰和大字号层级。
- 延续当前项目的森林绿、暖白和书卷气质。
- 不直接使用参考软件的黄色强调色、大幅摄影背景或品牌化图标。
- 学习页可使用非常轻的暖白纸张渐变；深色模式使用深绿黑渐变。
- 卡片最大宽度约 `720px`，桌面居中；移动端铺满可用宽度。

### 9.2 反馈颜色

| 行为 | 颜色用途 |
| --- | --- |
| 认识 | 项目现有绿色 `--good` |
| 模糊 | 琥珀色 `--warn` |
| 不认识 | 柔和红色 `--bad` |

颜色只用于按钮下划线、状态点或短暂反馈，不铺满整个按钮，避免视觉噪声。所有状态同时使用文字和图形表达，不能只依赖颜色。

### 9.3 响应式布局

- 桌面：底部操作区居中排列，支持鼠标和键盘。
- 平板：维持居中卡片，按钮扩大触控区域。
- 手机：三个评价按钮固定在安全区上方，答案内容可滚动。
- 高度较小时，减少上下留白，但单词、释义和主操作始终可见。

### 9.4 无障碍

- 所有音频按钮提供可读标签，例如「播放美式发音」。
- 键盘焦点清晰可见。
- 支持 `prefers-reduced-motion`，关闭翻页或渐入动画。
- 正文字号不低于 16px，辅助文本不低于 13px。
- 回忆阶段不自动抢焦点，防止空格快捷键意外触发页面滚动。

## 11. 数据设计

### 11.1 `vocab_word` 扩展字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `memory_stage` | Integer，默认 0 | 当前记忆阶段 0–7 |
| `due_at` | DateTime，可空 | 下次复习时间；新词为空 |
| `first_learned_at` | DateTime，可空 | 首次完成学习时间 |
| `last_reviewed_at` | DateTime，可空 | 最近正式评价时间 |
| `last_rating` | String，可空 | `known / fuzzy / unknown` |
| `known_streak` | Integer，默认 0 | 连续认识次数 |
| `lapse_count` | Integer，默认 0 | 遗忘次数 |
| `suspended_at` | DateTime，可空 | 非空代表暂缓学习 |

现有 `status` 字段暂时保留以兼容现有接口与导出功能，但由服务端根据学习进度维护。后续稳定后可以改为计算属性。

### 11.2 `vocab_review_log`

每次正式评价保留一条不可变记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer | 主键 |
| `vocab_id` | ForeignKey | 单词 ID |
| `session_id` | String | 所属会话 |
| `mode` | String | `learn / review / mixed` |
| `rating` | String | `known / fuzzy / unknown` |
| `stage_before` | Integer | 评价前阶段 |
| `stage_after` | Integer | 评价后阶段 |
| `due_before` | DateTime，可空 | 原到期时间 |
| `due_after` | DateTime | 新到期时间 |
| `response_ms` | Integer，可空 | 回答耗时，暂只记录不参与算法 |
| `reviewed_at` | DateTime | 评价时间 |

日志用于完成页统计、未来算法调优和排查异常。删除生词时级联删除其复习日志。

### 11.3 `vocab_study_settings`

单机单用户场景只保存一行：

- `new_group_size = 5`
- `review_group_size = 10`
- `daily_new_limit = 20`
- `task_order = review_first`
- `autoplay_audio = true`
- `preferred_audio = us`
- `show_context_during_recall = true`

### 11.4 会话恢复

建议保存轻量的 `vocab_study_session`：

- 会话 ID、模式、创建时间、完成时间。
- 初始单词 ID 列表。
- 当前游标。
- 待补强队列。

会话本身只负责恢复页面；复习结果以 `vocab_review_log` 和单词当前字段为准。

### 11.5 数据库迁移

当前项目只调用 SQLAlchemy `create_all`，它不会为已有 SQLite 表增加字段。实现本功能时必须增加显式迁移机制：

- 推荐引入 Alembic，建立可追踪的 schema 版本。
- 首次迁移给所有已有生词设置 `memory_stage = 0`、`due_at = NULL`，保留原有单词内容。
- 原状态为 `mastered` 的词不直接推断记忆阶段；建议迁移后设为 `stage = 6`，并安排次日进行一次校准复习。
- 迁移前由桌面应用备份数据库文件，失败时不启动新版本服务并提示恢复方式。

## 12. API 设计

### 12.1 首页摘要

`GET /api/vocab/study/summary`

返回：

- 今日到期数量。
- 今日剩余可学习新词数量。
- 新词总数、学习中数量、已掌握数量。
- 是否存在未完成会话。
- 当前设置。
- 学习卡片可包含 `pronunciation_weak` 提示字段，由现有 `WeakWordCount` 推导。

### 12.2 创建会话

`POST /api/vocab/study/sessions`

请求：

```json
{
  "mode": "review"
}
```

服务端根据设置、到期时间和排序规则生成固定队列并返回会话。由服务端选词，避免刷新页面后队列变化。

### 12.3 获取与恢复会话

- `GET /api/vocab/study/sessions/{session_id}`
- `GET /api/vocab/study/sessions/active`

### 12.4 提交评价

`POST /api/vocab/study/sessions/{session_id}/reviews`

```json
{
  "vocab_id": 42,
  "rating": "fuzzy",
  "response_ms": 3850
}
```

服务端必须：

1. 校验该词属于当前会话。
2. 防止同一正式卡片重复提交。
3. 在单个数据库事务中写日志并更新单词排期。
4. 返回新的阶段、下一次复习时间和是否需要组内补强。

### 12.5 完成会话

`POST /api/vocab/study/sessions/{session_id}/complete`

返回认识、模糊、不认识数量、用时和下一次预计复习摘要。

### 12.6 设置

- `GET /api/vocab/study/settings`
- `PATCH /api/vocab/study/settings`

所有数值由后端再次校验范围，不能只依赖前端限制。

## 13. 特殊情况

- 单词被删除：未完成会话遇到该 ID 时跳过，不报错中断。
- 单词被暂缓：已创建会话中尚未评价的卡片跳过。
- 释义为空：仍展示单词、来源原句和可用发音，并提示「暂无释义」。
- 音频文件不存在：隐藏对应按钮，不能留下无效操作。
- 同一词重复加入：沿用当前 `word_norm` 唯一约束，不创建第二份学习进度。
- 到期词很多：显示真实数量，按组加载，不把未展示的词标记为已处理。
- 用户修改系统时间：日志时间保持不变；异常的未来时间不自动清除，提供「重置学习进度」解决。
- 连续快速点击：评价按钮提交后立即锁定，防止重复写日志。
- 网络不可用：本地 API、现有释义和本地音频仍可正常学习。

## 14. 统计衔接

第一版建议在现有统计页增加：

- 首次学习数 `vocab_learned_count`。
- 完成正式复习数 `vocab_review_count`。
- 当日认识率：`认识 / 正式评价总数`。

组内补强不计入正式复习数和认识率分母。原有 `new_word_count` 仍表示「新增到生词本」，不能改成「首次学习」，避免历史指标语义变化。正式评价、复习日志和每日统计应在同一个数据库事务中写入。

## 15. 验收标准

### 首页

- 能正确显示当前时间已到期的复习数量。
- 能正确应用每组数量和每日新词上限。
- 到期任务、新词任务和全部单词列表互不影响。

### 会话

- 每次只展示一个单词，并先回忆后显示答案。
- 三档评价均能正确保存并计算下一次时间。
- 模糊与不认识的词能按规则在组内再次出现。
- 刷新、关闭页面或重启桌面应用后能恢复未完成会话。
- 快捷键与按钮产生相同结果，且不会重复提交。

### 排期

- 认识推进阶段，模糊缩短间隔，不认识重置阶段。
- 到期判断覆盖等于当前时间的情况。
- 已掌握单词答错后自动回到学习中。
- 跨日、逾期和修改时区不会丢失复习任务。

### 兼容性

- 旧数据库升级后原有生词、释义、原句和音频路径不丢失。
- 未配置 DeepSeek 或 Azure 时可以完成学习与复习。
- 原有筛选、删除、发音与导出功能继续可用。

## 16. 建议实施顺序

1. 引入数据库迁移并增加学习字段、日志、设置和会话表。
2. 完成排期服务及其单元测试。
3. 完成摘要、会话、评价和设置 API。
4. 重构生词本首页，接入今日任务摘要。
5. 完成沉浸式学习会话页和响应式样式。
6. 补齐会话恢复、快捷键、异常状态和统计。
7. 使用既有数据库副本完成迁移回归，并进行桌面端打包验证。

## 17. 待确认的产品决策

以下项目不阻碍第一版按推荐值实现，但建议在开发前确认：

1. 已有手动标记为「已掌握」的单词，是迁移为待校准复习，还是继续视为完全掌握。
2. 新词首次出现时是否显示来源原句。推荐显示挖空原句，设置中允许关闭。
3. 今日任务是否严格要求先复习。推荐只提示、不强制。
4. 是否在第一版统计页展示认识率。推荐加入，但不增加复杂趋势图。

## 18. DeepSeek 评审意见取舍

### 18.1 接受并纳入

| 建议 | 结论 | 纳入方式 |
| --- | --- | --- |
| 用排程替代纯手动三态 | 接受 | 状态由学习记录自动维护；手动操作改为重置或暂缓 |
| 到期词按 `due_at` 排序 | 接受 | 逾期最久的单词优先 |
| 学习页采用正面回忆、背面答案 | 接受 | 已设计为「主动回忆 → 答案确认」两阶段 |
| 支持键盘操作和会话小结 | 接受 | 使用 `1–3`、空格、回车和退出快捷键 |
| 打通跟读弱词信息 | 部分接受 | 显示「发音待加强」，并作为同等到期时的次级排序信号 |
| 增加复习统计 | 接受 | 新增首次学习数与正式复习数，保留现有新增生词指标的语义 |
| 保留浏览、发音、删除和导出 | 接受 | 新学习模式叠加在现有生词管理能力上 |

### 18.2 不直接采用

| 建议 | 结论 | 原因 |
| --- | --- | --- |
| 使用四档 `Again / Hard / Good / Easy` | 不采用 | 用户参考界面和本方案均以「认识 / 模糊 / 不认识」为核心；三档认知负担更低，也更适合中文界面 |
| 第一版直接使用简化 SM-2 | 不采用 | 给出的公式缺少首次复习等边界定义，且短间隔取整可能长期停在 1 天；第一版的阶段间隔更直观、可测试 |
| 新词创建时令 `due_at = created_at` | 不采用 | 会混淆「待首次学习」与「已学习后到期复习」；新词的 `due_at` 应为空 |
| `interval >= 30 天` 即已掌握 | 不采用 | 单次进入 30 天间隔不足以证明稳定掌握；本方案要求达到 60 天阶段且连续 3 次认识 |
| 弱词默认判为「困难」 | 不采用 | 跟读发音薄弱不等于词义记忆薄弱，系统不能替用户提交主观记忆评价 |
| 按 WeakWordCount 直接高权重置顶 | 不采用 | 该计数当前只增不减，旧的发音问题会永久占据队列；仅在同等到期条件下辅助排序 |
| 每轮默认 20 张 | 不采用 | 已按产品决策确定为新学 5 个、复习 10 个 |
| 只提供无状态 queue 接口 | 不采用 | 无法可靠处理刷新恢复、组内重现和重复提交；采用服务端会话模型 |
| 复习时累加原 `new_word_count` | 不采用 | 该字段当前表示加入生词本，修改语义会破坏历史统计一致性 |
| 保留循环点击手动三态 | 不采用 | 容易与自动排程互相覆盖；替换为语义明确的重置、暂缓等操作 |

### 18.3 后续版本再评估

- 当积累足够复习日志后，可比较阶段间隔与完整 SM-2、FSRS 等自适应算法的实际效果。
- 若未来让 `WeakWordCount` 支持衰减或记录最近发生时间，可以提高它在队列排序中的权重。
- 若用户认为三档反馈区分度不足，再考虑增加「轻松」档；第一版不预留第四个主按钮。
